# Learning Learning

A practitioner's handbook that answers one question: how do we deliver the best training possible today?

Built with React, Vite and React Router. No UI framework. Styles are plain CSS on top of variables generated from the design tokens. Both typefaces (Bricolage Grotesque, Hanken Grotesk) are self-hosted through Fontsource.

## Run it

```
npm install
npm run dev        # local development
npm run build      # production build in dist/
npm run preview    # serve the production build
npm run build:single   # one self-contained HTML file in dist-single/, for sharing a preview
npm run tokens     # regenerate src/styles/tokens.css after editing src/content/tokens.json
```

Routing uses hash addresses (`/#/playbook`) so the build works on any static host. For clean addresses set `VITE_ROUTER=browser` and add a fallback rule on the host.

The "Choose a format" page stays hidden unless `VITE_SHOW_FORMATS=true`.

## What is built

| Page | Address | State |
|---|---|---|
| Home | `/` | From the signed-off board, then changed on review: every mistake, finding, myth and case study is on the page, lists run in stage order, and counts are gone |
| Playbook landing | `/playbook` | From the signed-off board, without topic counts |
| Stage pages, 1 to 9 | `/playbook/stage-n` | One template, without counts |
| Topic pages, 89 | `/playbook/stage-n/topic-title` | One layout: the situation and the practice on the first screen, then the reasons, an example and the sources. Topics are written from blocks (text, steps, diagram, research card, example, cards to remember, mechanic links, links out). One topic has labelled sample copy; the rest say "Not written yet" |
| Learning mechanics | `/playbook/mechanics` and detail pages | Moved from the Toolkit into the Playbook |
| Toolkit | `/toolkit`, `/toolkit/methods`, `/toolkit/recipes`, `/toolkit/templates` and their detail pages | First version for review, on real data exported from the toolkit workbook |
| Evidence | `/evidence`, `/evidence/how-we-rate`, `/evidence/numbers`, `/evidence/studies`, `/evidence/reading` | First version for review. Glossary is outline only |
| Case studies | `/case-studies`, `/case-studies/slug` | First version for review: 3 drafts, 9 still to research |
| About, Search | `/about`, `/search` | First version for review. Search works across topics, mistakes, findings, methods, mechanics, recipes and case studies |

Only Home, the Playbook landing and the Stage page were signed off as designs. Everything else is a first version built from the same pieces and still needs sign-off.

The toolkit JSON in `src/content/toolkit/` is generated by `scripts/export-toolkit.py` from the toolkit workbook. It leaves out the source list, the case notes and provider names, and blanks variant descriptions that only repeat their parent.

## Where things are

```
src/content/        playbook.json, home.json, site.json, tokens.json: all copy and structure
src/styles/         tokens.css (generated), app.css (ported from the boards, same class names), pages.css (pages added since)
src/components/     shared components listed in the design spec
src/pages/          Home, Playbook, Stage, Topic, Toolkit, Evidence, Cases, About, Search, Outline, NotFound
scripts/            build-tokens.mjs, export-toolkit.py
```

To change copy, edit the JSON. Link labels to topics are generated from the topic title, so they cannot drift.

## Where the build differs from the boards

1. Stages with one part (6, 7, 8) open that part on load and drop the "Open all parts" control.
2. Topics with no evidence rating show five empty bars and "Not yet rated".
3. Stages 2 to 8 say on the page that their titles are drafts and their evidence is not rated.
4. Topic link labels on Home are generated from the topic, so a few read differently from the board.
5. Headings never break inside a hyphenated word such as "e-learning".
6. Phone widths: the myth section no longer overflows, the stage discs on a stage page shrink to 36px so all eight fit one row, and the "Open the myth file" link aligns left when it wraps.
7. The myth card is announced to screen readers when it changes, not only the counter.
8. Added: a skip link, a page title per page, focus moved to the content on navigation, a placeholder favicon.

## Numbering

One rule: a number in a coloured disc is a stage (1 to 9) or a topic in that stage (1.1 to 1.17). Parts of a stage and the six parts of a topic are named, not numbered. The only other numbered lists are real sequences: the steps under "Do this" and the order of events in a recipe. Lists on Home are grouped under their stage.

## Rules that must hold

Nothing confidential. Nothing unverified shown as checked. No invented evidence. Colour means stage; evidence is letter, bars and word. Practice first. See the build pack brief in the Project for the full list.
